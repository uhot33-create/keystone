# 暮らし帳

メールアドレスでログインして使う、個人用の記録アプリです。

## 概要

ログイン後のメニューから、次を使います。

- **わんカロリー** — 愛犬の食事カロリー、体重、目安カロリー、推移グラフ
- **喫煙管理** — 1日の上限本数、減算、毎日0時（日本時間）のリセット、達成バッチ
- **お散歩メモ** — 出会った子のカード（犬種・画像・虹渡り）と、GPX の散歩ログ
- **通院履歴** — 通院の予定と記録、次回に先生へ伝えるメモ
- **カップ麺** — 品名と在庫数

メニュー下部には、今日は何の日、格言、小話、犬の豆知識、占い、犬の話題を出せます。表示のオンオフはアカウントごとに保存します。

## サーバー実行環境

- アプリ: [Vercel](https://vercel.com)（Nitro の `vercel` プリセット。Hobby 想定）
- データベース: Supabase の Postgres。接続は `DATABASE_URL`（プールは transaction mode の 6543）
- 画像: Vercel Blob。データベースには URL だけを保存する
- 毎日 0:00（日本時間）の定期実行: Vercel Cron。定義は `vite.config.ts` の Nitro 設定（`0 15 * * *` UTC）
- `DATABASE_URL` が無いローカル起動だけ、埋め込みの Postgres（PGLite）を使う。再起動でデータは消える

## 環境変数

`.env` ファイルは使いません。Vercel の Project Settings → Environment Variables に設定します。

| 名前 | 必須 | 用途 |
| --- | --- | --- |
| `DATABASE_URL` | 本番は必須 | Supabase の接続文字列 |
| `BETTER_AUTH_SECRET` | 必須 | セッション署名用。32文字以上 |
| `BETTER_AUTH_URL` | 必須 | 公開 URL。末尾スラッシュなし |
| `VITE_AUTH_ENABLED` | 必須 | `true` |
| `BLOB_READ_WRITE_TOKEN` | 画像を使うとき | Vercel Blob の読み書きトークン |
| `RESEND_API_KEY` | 再設定メール | Resend の API キー |
| `RESET_EMAIL_FROM` | 任意 | 再設定メールの差出人。未設定時は Resend の試験用差出人 |
| `CRON_SECRET` | 本番の Cron では必要 | 16文字以上のランダム文字列。Vercel Cron が `Authorization: Bearer` で送る |

## 運用

### インストール方法

```bash
npm install
npm run dev
```

開発サーバーは `http://localhost:8080` です。本番は GitHub の `main` を Vercel がビルドします。`npm run build` のあと `migrations/*.sql` が未適用分だけ実行されます。

### パスワード再設定

1. ログイン画面の「パスワードを忘れた」からメールアドレスを送る
2. 届いたリンク（1時間有効）で新しいパスワードを設定する
3. ログイン中は右上の丸から「パスワードの再設定」でも変更できる

送信には `RESEND_API_KEY` が必要です。未設定だと再設定メールは送れません。

### 散歩ログのインポート

お散歩メモの「散歩ログ」で、GPS アプリが書き出した `.gpx` を選びます。距離、時間、地図の軌跡を保存します。一覧の名前は、軌跡の中心に一番近い都道府県・市区町村・町名です。住所が取れないときだけ、GPX内の名前かファイル名を使います。一覧は年、その中の月ごとに分かれます。今年は開いた状態で、それより前の年は閉じています。月の行は、月・時間・距離・横棒の1行です。月を押すと日別が開きます。日別は2行です。1行目は日と時刻（月は出さない）・時間・距離・横棒、2行目は名前です。横棒は、月は同じ年の中、日は同じ月の中で比べます。今月だけ、最初から開いています。地図は月の「地図」から開きます。中心が同じ700m四方の軌跡だけを同じ地図に重ね、それより離れた場所は別の地図です。前後の散歩は一本の線につなぎません。削除は各ログの詳細です。

iPhone の Geographica などは「書き出し → GPX → ファイルに保存」したあと、取り込み画面の「ブラウズ」から選びます。ファイルは 8MB 以下です。

### カロリー集計バッチ

毎日 0:00（日本時間）に、Vercel Cron が `GET /api/cron/calorie-summary` を呼びます。スケジュールは `vite.config.ts` の `0 15 * * *`（UTC 15:00）だけに書きます。`vercel.json` にも書くとデプロイが重複エラーになります。Hobby では、0時ちょうどではなく、その時刻から最大約1時間の幅で動くことがあります。

`CRON_SECRET` があるときは、`Authorization: Bearer <CRON_SECRET>` が一致した呼び出しだけ処理します。無い、または違うときは 401 で止まります。

処理の順は次のとおりです。途中経過は `cron_runs` に残します。

1. 実行行を `cron_runs` に作り、開始時刻を書く。
2. 喫煙管理の日次リセットを先に行う。ここで失敗しても、あとの処理は続ける。
3. 散歩ログは、前回の集計から増減した月と、区切りの大きさが変わった月だけ作り直す。変わっていない月の軌跡は読み直さない。軌跡の中心が同じ700m四方のものだけを同じ地域にし、それ以外は分けて `walk_month_tracks` に保存する。各地域の中でも、前後の散歩は一本の線につなげない。ここで失敗しても、カロリー集計は続ける。取り込みや削除では作り直さない。
4. 登録されている犬を1頭ずつ、今日（日本時間）を基準に再集計する。
5. 成功なら `cron_runs` を成功で閉じ、`{ ok: true, dogs, asOf, smoking, walks }` を返す。カロリー集計が失敗したときは失敗で閉じ、HTTP 500 を返す。

カロリー集計（1頭ごと）:

1. 今日から約5年分（366日×5）の日別データを読む。
   - `calorie_logs` を日ごとに合計する。小数第2位以下は切り捨て、小数第1位まで。
   - `dog_weight_logs` から、その日の体重を読む。
2. 週（月曜始まり〜日曜）、月（1日〜月末）、年（1月1日〜12月31日）に分ける。進行中の週・月・年は、終わりを未来日にせず、今日までに切る。
3. 各期間のカロリーは、期間内の日別合計を足し、再び小数第1位で切り捨てる。
4. 各期間の体重は、期間の最終日に記録があればその値。無ければ期間内で最も新しい記録。1件も無ければ空。
5. 週・月・年だけを `calorie_period_stats` に保存する（同じ犬・期間なら上書き）。日別の明細は `calorie_logs` のまま残し、このバッチでは日別テーブルを作りません。
6. 目安カロリー（`calorie_period_guides`）はこのバッチでは計算しません。プランを保存したときに書き込みます。グラフ表示は、締まった期間を `calorie_period_stats` から読み、今日を含む期間だけ明細を足します。

同じジョブの喫煙リセット:

- `smoking_settings` を全ユーザー見る。
- 前回リセットした日（`period_started_at` UTC時刻を日本時間に変換後の日付）が今日と同じなら何もしない。経過時間ではなく、日付だけを比べる。
- 今日より前なら、残数を1日の上限に戻し、超過フラグを消し、リセット日を今日の0時にする。
- 戻したユーザーだけ、昨日までの達成バッチを確定する。
